04模型結果：誠實的版本

預測台中市門診類流感就診佔比。模型目前多數情況輸給「假設下週跟這週一樣」。 這是結果，不是待修的 bug。

設定模型 MAE持平基準方向準確率判定
t+1，預測水準值0.1836 pp0.1175 pp49.7% 差 56%
t+1，預測變化量0.1320 pp0.1175 pp56.1% 差 12%
t+2，預測變化量0.1682 pp0.1687 pp63.8% 僅勝 0.3%
t+1，隨機切分0.1810 pp0.1479 pp51.4% 刻意的洩漏對照

唯一一次調整是有結構理由的，不是試到贏為止。 梯度提升樹無法外推——要它預測水準值，它只能回傳看過的水準值。 改成預測「相對上週的變化」後，持平基準變成模型的零預測，t+1 從 0.1836 降到 0.1320。 仍然輸。四次結果全部入庫，包含輸的那些。

t+2 那個「贏」不要當成贏。 0.1682 對 0.1687，448 個 fold 上差 0.3%，那是雜訊。 beats_baselines 是嚴格小於，所以它對 0.3% 和 30% 一樣大聲說 YES—— 真正有意義的是 63.8% 的方向準確率，而方向本來就是排班決策要的東西。

05本階段的方法論

這個平台反覆栽在同一件事上，值得單獨講給長官聽。

「一句描述機制的註解，不是那個機制存在的證據。」 本週四次：Vault 宣稱會換憑證（做不到）、去重宣稱抓得到衝突（只比鍵不比值）、 CI 宣稱測 drain（0.3 秒逾時，兩個方向都在說謊）、憑證刷新照著 API 宣稱的 3600 秒排程（真實壽命 1200 秒）。

對策是負控制，不是更多測試。 每一個新檢查都故意寫壞一次，確認它會失敗，再還原。 本階段共注入 9 次刻意破壞，全部被抓到。 一個從沒失敗過的檢查，證據等級等同於沒有檢查。
