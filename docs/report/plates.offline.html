要看的一件事：LLM 複審接在流程裡，但它沒有否決權——結論是建議性的，不會讓燈變紅。把判斷權交給模型，和把判斷權交給沒人看的紅燈，是同一種失效。真正擋下發布的是真人 PROMOTE。

另一件要看的：DAST 執行中系統與DAST 掃到多少是兩個節點。掃描回報 PASS，只代表掃到的路由沒有問題；掃不到的寫入端點在原理上碰不到。所以涵蓋率單獨成為一個會變色的數字，而不是藏在 PASS 後面。

要看的一件事：血緣是硬條件——「檔案列數 = 接受 + 拒絕 + 重複」不成立的批次，不會進到契約。但算術成立不代表資料有收進來：一個來源可以每一列都被拒絕、而帳仍然是平的，所以抓取品質單獨問。週↔日曆對照則是刻意誠實的那一格：對不到日曆日的週次會被標出來，把它塗綠只會讓後面每一個用到週定義的數字，帶著一個沒人記得的假設。

要看的一件事：閘門有兩層保證。第一層是發布程式只挑贏過基準的訓練；第二層是閘門沒有被繞過回頭問資料本身——每一筆已發布預測是否都追得回一次贏的訓練。「程式碼這樣寫」不是證據，一個被改掉的條件式不會留下痕跡，所以問的是結果，不是程式。

要看的一件事：最上面那一層存在，是因為下面全部正常運作，和有人被告知，是兩件事。這個平台實測過一次 73.7 小時的監測中斷：探針每 15 分鐘忠實把它寫進證據，寫了三天約 200 份，沒有人打開過任何一份。所以「看得到的一層」不是裝飾，它是這張圖裡唯一負責讓下面各層產生後果的部分。

來源 · platform/statusdag/dag.py 全部 layer 依相依方向重新分組；機器層見 ADR-0008

怎麼確認這些圖還是真的：節點與連線來自 platform/statusdag/dag.py； bash platform/tests/test_offline_report.sh 逐一比對——板面多了一個節點、少了一條邊、或圖上還留著已退役的名字，測試就轉紅。

現況在哪裡看：落地百分比、三態判定（已落地／工程欠債／受研究上限）與誰欠什麼，在階段報告；它每 15 分鐘由板面重新產生，所以永遠比這份圖新。

同一個原則，2026-09-01 當天實測的三個例子：DAST 涵蓋 40%、健康監測涵蓋 83.6%、 而秘密輪替閘門的 ROTATION PASS 是在三把秘密全部豁免的情況下、對空集合量化得出的。 三個數字都不好看，而它們在被量出來之前全部顯示為綠色。 一條說「幾乎什麼都沒檢查」的綠燈，比一個誠實的低數字危險得多。

其中兩個的守衛早就存在，只是擋錯了那種空。輪替稽核有一段註解寫著 「An empty tree is not a pass」，擋的是「一個秘密都沒有」；平台漂移進的是 「每個秘密都被豁免」，直接繞過去。空集合守衛是針對你當時想像得到的那種空寫的。

當天下午，宿主休眠把整組容器停掉，這件事自己示範了一次。恢復之後 Compose 那份副本回到靜態密碼、K8s 那份是 Vault——和當天早上完全對調， 而中間沒有任何人做過任何決定。唯一發現它的，是幾小時前才寫下的 「兩份副本憑證模型必須相同」那條斷言。同一次停機也被健康彙總記了下來： 失敗快照 201 → 205，涵蓋率 83.6% → 83.9%。 今天建的量測，當天就抓到一次真實事件。
