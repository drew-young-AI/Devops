怎麼重跑這些圖背後的東西：節點與連線來自 platform/statusdag/dag.py， 現況數字來自 bash platform/tests/run_all.sh 與 python3 platform/statusdag/dag.py。 圖上任何一個方塊，都對得到板面上一個會自己變色的節點。

刻意留著的三個黃燈：週↔日曆對照（待疾管署查證）、上線閘門（模型還沒贏基準）、資料來源已 14 天未更新。 這三個不是待辦事項漏了，是系統正確地說出它現在不知道什麼——把它們塗綠是最容易做、也最沒有價值的一件事。

同一個原則，三個當天實測的例子：DAST 涵蓋 40%、健康監測涵蓋 83.6%、 而秘密輪替閘門的 ROTATION PASS 是在三把秘密全部豁免的情況下、對空集合量化得出的。 三個數字都不好看，而它們在被量出來之前全部顯示為綠色。 一條說「幾乎什麼都沒檢查」的綠燈，比一個誠實的低數字危險得多。

其中兩個的守衛早就存在，只是擋錯了那種空。輪替稽核有一段註解寫著 「An empty tree is not a pass」，擋的是「一個秘密都沒有」；平台漂移進的是 「每個秘密都被豁免」，直接繞過去。空集合守衛是針對你當時想像得到的那種空寫的。

當天下午，宿主休眠把整組容器停掉，這件事自己示範了一次。恢復之後 Compose 那份副本回到靜態密碼、K8s 那份是 Vault——和當天早上完全對調， 而中間沒有任何人做過任何決定。唯一發現它的，是幾小時前才寫下的 「兩份副本憑證模型必須相同」那條斷言。同一次停機也被健康彙總記了下來： 失敗快照 201 → 205，涵蓋率 83.6% → 83.9%。 今天建的量測，當天就抓到一次真實事件。
